Callback Hell:
--------------

Callback Hell is a situation where multiple asynchronous operations are nested inside callbacks, 
creating deeply indented code that is difficult to read, maintain, and debug. 


function first(cb) {
  console.log("First Function")
  cb();
}

function second(cb) {
  console.log("Second Function")
  cb();
}

function third() {
  console.log("Third Function")
}

first(() => {
  second(() => {
    third()
  });
});


//To avoid the callback- callback hell -> Promise was introduced.

Promise
--------

Promise is a JavaScript object used to handle asynchronous operations (like API calls, 
file read, timers) and gives a result in the future

//syntax 

let foodAvailable = false;

let promise = new Promise((resolve, reject) => {
  if (foodAvailable) {
    resolve("food is ready");
  } else {
    reject("no delivery");
  }
});

promise
  .then(result => console.log(result)) //handel succeeds -> reslove
  .catch(error => console.log(error))  // handles error -> reject

Promise States:
---------------
1. Pending   -> Initial state
2. Fulfilled -> resolve() called
3. Rejected  -> reject() called


Async/Await (introduced in ES2017)
----------------------------------
async/await was introduced in ES2017, async function always returns a Promise and await pauses 
execution until the Promise is resolved or rejected.

let foodAvailable = false;

function orderFood() {
    return new Promise((resolve, reject) => {

        if (foodAvailable) {
            resolve("Food is ready");
        } else {
            reject("No delivery");
        }

    });
}

async function checkFood() {

    try {
        const result = await orderFood();
        console.log(result);
    } catch (error) {
        console.log(error);
    }

}

checkFood();

Introduction to Playwright:
---------------------------

Playwright is an open-source browser automation framework developed by Microsoft that is 
used to automate and test modern web applications across Chromium, Firefox, and WebKit using
 a single API.

Features 
---------

Microsoft Open Source Tool
Cross-browser automation (Chromium, Firefox, WebKit)
Cross-platform support (Windows, Linux, macOS)
Auto-waiting capability
Built-in Test Runner
Supports multiple programming languages (JavaScript, TypeScript, Java, Python, .NET)
API Testing support
Mobile device emulation
Network interception and mocking
Screenshots and video recording
Trace Viewer for debugging
Multiple Browser Contexts (isolated sessions)
Headless and Headed execution
Automatic retries for flaky tests

 Browser -> Context -> Page
 ----------------------------

Browser: Actual browser engine (Chromium, Firefox, WebKit)

Context: Isolated environment like an incognito session

Page: A single tab within a context

const browser=await chromium.launch({headless:false,channel:"msedge"})
const context=await browser.newContext()
const page=await context.newPage()

Steps to Add Report, Screenshot, Video, and Trace in Playwright Config
----------------------------------------------------------------------

export default defineConfig({

  // By default, Playwright waits for a maximum of 30 seconds (30000 ms)
  // for each test. You can override this timeout using the 'timeout' option.

  timeout: 60000,

  // Generate an HTML report and open it automatically after execution
  reporter: [['html', { open: 'always' }]],

  use: {
    //headless option controls whether the browser runs with or without a visible UI.
    headless: false,

    // Capture a screenshot for every test
    screenshot: 'on',

    // Record video for every test
    video: 'on',

    // Capture trace for every test
    trace: 'on'
  }

});


The Playwright Config File is the central configuration file of a Playwright project
It defines how your tests should run, which browsers to use, timeouts, retries, reporters, 
screenshots, videos, traces, and many other settings.

testDir-> Specifies where test files are located.

timeout-> Maximum time allowed for a single test.

retries-> Number of times Playwright reruns a failed test

workers-> Controls parallel execution.

| Workers                   | fullyParallel | Spec Files | Projects                    | Workers Used       | Result                                                             |
| ------------------------- | ------------- | ---------- | --------------------------- | ------------------ | ------------------------------------------------------------------ |
| 1                         | false         | 1          | 1                           | 1                  | Tests run sequentially.                                            |
| 1                         | true          | 1          | 1                           | 1                  | Tests still run sequentially because only 1 worker is available.   |
| 1                         | true          | 2          | 1                           | 1                  | Spec files run one after another.                                  |
| 2                         | true          | 2          | 1                           | 2                  | Two spec files can run in parallel.                                |
| 4                         | true          | 4          | 1                           | 4                  | Four spec files can run in parallel.                               |
| 1                         | true          | 1          | 3 (Chrome, Firefox, WebKit) | 1                  | Projects run one after another because only 1 worker is available. |
| 3                         | true          | 1          | 3                           | 3                  | Chrome, Firefox, and WebKit can run in parallel.                   |
| Default (workers not set) | true          | Multiple   | Multiple                    | Based on CPU cores | Playwright automatically decides the worker count.                 |


fullyParallel->Run tests in parallel.

forbidOnly->Prevents accidental commits of .only

process.env->A Node.js object containing environment variables. 
process.env.CI->Returns the value of the CI environment variable.

Local Machine:
--------------
process.env.CI = undefined (usually)
forbidOnly: !!process.env.CI
forbidOnly: false, Hence test.only() is allowed in local

CI Pipeline (Jenkins/GitHub Actions/Azure DevOps):
-------------------------------------------------
forbidOnly: !!process.env.CI
process.env.CI = "true"  //Error: test.only is not allowed and Fails execution in Pipeline
forbidOnly: true

! (Single NOT):Opposite boolean value
--------------------------------------
!true  -> false
!false -> true

!! (Double NOT):Converts any value into a boolean:
--------------------------------------------------

!!undefined -> false  //hence .only is allowed in local
!!0         -> false
!!""        -> false
!!"hello"   -> true
!!1         -> true

reporter-> Generates test reporter

use Block-> Settings inside use apply to every test

ex: use: {

  screenshot: 'on',
  video: 'on',
  trace: 'on'  //Useful for debugging failures.
